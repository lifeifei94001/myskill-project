# 逆向推演风险评估（Pre-mortem）与方案点选拍板规范

**目的：** 写代码之前，先假设“功能上线后彻底翻车了”，倒推翻车原因，把高风险点连同代码级应对方案和验证方式一次列全，再给出开发方案与**「结构化点选拍板卡」**。翻车点在设计阶段用几行字堵住，比上线后返工重写便宜得多，既省时间也省 token。

**位置：** 开场业务澄清之后、写代码之前。顺序固定：`开场点选澄清 → 逆向推演风险评估 → 开发方案 + 拍板点选卡 → 写代码`。

---

## 一、按模式选档位（别一刀切，小任务别写成大报告）

| 模式 | 档位 | 要求 | 之后怎么做 |
|------|------|------|-----------|
| 快速脚本 | **轻量版** | 高风险 ≤5 条，和“逻辑确认总结”放在同一轮输出 | 若无新的口径歧义点 → 同轮直接生成代码；若有 → 附点选卡等用户回复 |
| 桌面工具 | **完整版** | 高风险 ≤8 条，五个维度过一遍 | 输出开发方案 + **方案拍板点选卡**，等用户回复“默认”或编号后再写代码 |
| Web 工作台 / 云端双模 | **完整版** | 高风险 ≤8 条，覆盖并发/状态保持/毛玻璃零白块与云端九条铁律 | 输出五层架构方案 + **方案与视觉/插件拍板点选卡**，等用户确认后再写代码 |
| 开源调研 → 落地实现 | **完整版** | 调研阶段先给候选对比与选型点选卡；选定路径后、写代码前做完整推演 | 同上 |
| 修改已有代码 | **改动版** | 只评估本次改动的影响面、数据兼容与回归风险（≤4 条） | 同轻量版 |

**可跳过的情况：** 用户明确说“不用评估/直接写”，或只是改一个常量/调列宽这类微调。跳过时仍用一句话点出最大的 1 个风险并在代码里自动做好防护。

---

## 二、推演流程（4 步）

1. **设定情景**：开头写一句“假设【功能一句话】上线一周后翻车了，最可能死在以下几个地方：”。
2. **倒推穷举**：按下方五个维度筛查本次任务真实存在的隐患（只挑本次相关的，严禁套话抄表）。
3. **筛选分级**：
   - 🔴 **高风险**：必须配齐 **翻车场景 → 代码级应对方案 → 验证方式**
   - 🟡 **中风险**：一行一条简述防呆措施
   - 🟢 **低风险**：不写（省 token）
4. **绑定开发方案与拍板点选卡**：每个高风险编号（`R1`、`R2`…）必须映射到开发方案的具体模块/函数上，并在末尾附上带 `●` 默认推荐项的**「方案拍板点选卡」**。

---

## 三、五个维度的检查清单（按任务类型取相关项，不要全抄）

### 1. 数据与表头风险（所有模式必查）
- 表头首尾空格、全半角括号差异、原始表头重复或归一化后冲突（必须用 `match_headers` 两趟严格全等匹配 + 重复列报错阻断，严禁用 `in` 子串模糊匹配）
- 合并单元格导致下方行取值为空（需用 `build_lookup_dict` 向下摊平填充）
- 关联键含大小写/空格差异匹配不上，或右表关联键重复导致 Left Join 后主表行数翻倍膨胀（笛卡尔积灾难）
- 空值与脏数据去向：**严禁静默 `drop_nulls` 丢弃**！必须分流导出到 `异常空值明细` Sheet 或返回前端异常列表
- 过滤条件值为 `0`、`False` 或空字符串时，严禁用 `if FILTER_VAL:` 导致静默跳过

### 2. 业务逻辑与口径风险
- 财务口径（含税/不含税、记账日/到账日、负数代表退款还是冲销）
- 阶梯价临界点（`>=` 还是 `>`）、成色档位价格倒挂（需加 `np.maximum` 单调性防倒挂保护）
- 汇总对账：处理前后的总行数（正常行 + 异常行）与总金额是否守恒可核对

### 3. 环境、打包与云端配额风险
- **快速脚本**：Polars `engine="calamine"` 必须检 `fastexcel`、Pandas 必须检 `python_calamine`，错误退出必须 `sys.exit(1)`；目标 Excel 被 WPS/Excel 占用触发 `PermissionError`
- **桌面工具**：
  - `console=False` 无控制台模式下 `print` 触发 `AttributeError` 闪退（需顶部 `SafeWriter` 重定向）
  - 多开两个 EXE 实例同时写 JSON 字典库损坏文件（需 `threading.Lock` + 跨进程文件锁 `.lock` + `.tmp` + `.bak` + `os.replace`）
  - PyInstaller 开启 `upx=True` 触发杀软误报木马，或中文 EXE 名引发路径编码异常（`build.spec` 默认设 `upx=False` + 英文内部构建名）
  - WPS COM 属于“锦上添花 (`required=False`)”还是“强依赖 (`required=True`)”
- **Web 工作台（局域网 & 云端双模）**：
  - 逐条对照 `web_cloud_vercel_turso.md` 的**九条铁律**：① 纯 Python `TursoHttpConnection` + 本地 SQLite WAL `shm` 探针失败自动降级 `DELETE`；② 时间字段强制 `Optional[str]`；③ `executemany` 按 `min(120, 900 // 列数)` 分块 + 单条 `INSERT` 立即 flush 拿真实 `lastrowid` + `_pending_writes` 单事务原子提交；④ Vercel 只读目录写 `/tmp`；⑤ 剔除 `pandas/numpy/boto3` 保持 7 个核心包；⑥ `_get_clean_env` 防呆清洗且报错绝不回显 Token；⑦ `lifespan` + `get_session` 双保险幂等 `ensure_db_ready()`；⑧ 双重循环缓存与查询合并；⑨ **5GB 数据库配额红线（严禁存文件 BLOB）+ 仅在确需长期归档原文件时按需启用 Cloudflare R2 (`r2_storage.py`)**

### 4. 前端视觉、微交互与状态保持风险（Web 必查）
- **深色毛玻璃夹杂刺眼白块**：Element Plus 的表格、输入框、弹窗、下拉菜单未穿透覆盖导致白底外漏
- **切页或刷新跳回首页 / 闪现登录页**：`activeTab`、筛选条件、主题偏好与登录用户快照必须双写同步至 `localStorage` + URL Hash
- **大表卡顿与弱显卡掉帧**：`backdrop-filter` 严禁加在 `<tr>/<td>` 上，同屏模糊容器 ≤ 6 个，提供顶栏 `no-glass` 一键降级开关

## 四、输出模板（含「方案拍板点选卡」，直接套用）

```markdown

|---|---|---|---|---|
| **R1** | 数据与表头 | 具体翻车场景 | 具体函数/校验/分流设计 | 用什么测试或对账确认 |
| **R2** | 业务逻辑 | ... | ... | ... |
| **R3** | 性能/环境/配额 | ... | ... | ... |
| **R4** | 视觉与状态保持 | ... | ... | ... |

### 🟡 中风险防呆（一行一条）
- ……

## 🛠 开发方案概要
- **架构与目录结构**：（沿用当前模式 reference 规范，标明 R1~Rn 分别落在哪个文件）
- **核心数据流与事务边界**：（3~5 步说明输入 → 校验 → 计算 → 持久化/导出链路）
- **视觉与交互自检标准**（Web/GUI 适用）：（说明采用的主题预设、微交互插件组合，以及交付前执行的 Awwwards 七维自检闭环）

## ✅ 方案拍板点选卡（回复“默认”或指定序号即可开始生成代码）

**1. 风险兜底与架构方案确认**
- `●` **A. 按上述风险应对方案与模块划分执行（推荐默认）**
- `○` **B. 简化部分校验逻辑，追求极简代码量**
- `○` **C. 补充其他业务特殊边界**（请直接说明）

**2. 视觉主题与交互增强档位（Web / GUI 适用）**
- `●` **A. 🌌 星云毛玻璃 + 轻量微交互插件组合（`v-auto-animate` + 聚光灯卡片 + KPI 缓动 + 七维自检，推荐默认）**
- `○` **B. 🌸 霞光毛玻璃（暖白流光浅色主题）+ 轻量微交互**
- `○` **C. 🏛️ 先锋杂志风（Awwwards 非对称 Bento 网格 + 瑞士细线排版）**
- `○` **D. 纯净极简风（不加动效插件，仅保留基础主题）**

**3. 存储与部署形态确认（Web 适用）**
- `●` **A. 本地 SQLite WAL + 云端 Vercel & Turso 双模自适应，文件走内存流即用即走（推荐默认，零存储浪费）**
- `○` **B. 双模数据库 + 额外生成 `r2_storage.py` 接入 Cloudflare R2 永久归档原始上传文件**
- `○` **C. 仅本地/局域网运行，无需生成云端配置**
```

写完代码后，在交付说明末尾用**每条一行**附上「风险落实对照表（`R1 → 已在 xxx 处理`）」与「七维视觉自检清单」。
