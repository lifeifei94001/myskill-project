# 快速脚本模式

用于一次性数据处理任务（汇总/清洗/合并/透视/去重/TopN/生成模拟数据等），跑完就用，不需要长期维护成软件。这是最常见的触发路径。

## 开场流程：输出「结构化点选确认卡」（必须执行）

用户请求触发后，先根据用户已提供的信息预填默认项，对尚未明确的维度输出以下**ChatGPT 式结构化点选确认卡**（已知信息自动折叠或标为已确认，① 号核心动作不得跳过）：

```markdown
为了一次性写对脚本，请确认以下关键口径（带 `●` 为根据你描述预设的推荐项，直接回复 **“默认”** 或 **“1A 2B”** 即可）：

**1. 核心处理动作与计算口径**
- `●` **A. 分组汇总求和 / 计数（推荐默认）**：按指定维度分组，对数值列求和并按降序排列
- `○` **B. 多表关联匹配（Join / 替代 VLOOKUP）**：左表保留全部，右表去重后精确匹配合并
- `○` **C. 去重清洗 / 异常筛选 / TopN 提取**：按业务规则过滤并输出标准结果表
- `○` **D. 其他自定义规则**（请注明分组列、指标列与过滤条件）

**2. 空值与异常脏数据处理策略**
- `●` **A. 自动分流保护（推荐默认）**：正常行参与计算输出至「结果」Sheet，空值/异常行单独输出至同文件的「异常空值明细」Sheet，绝不静默丢弃
- `○` **B. 空值按 0 填充后参与计算**
- `○` **C. 遇到任何空值立即报错阻断**

**3. 产出形态与样式需求**
- `●` **A. 单文件 `.py` 极速脚本 + 新建标准 `.xlsx`（推荐默认）**：基于 Polars + FastExcel + XlsxWriter，双击或命令行直接跑
- `○` **B. 保留原 Excel 模板样式/公式回填**：基于 OpenPyXL 定向写入指定单元格（适合固定报表模板）
- `○` **C. Jupyter Notebook（`.ipynb`）分步交互式脚本**：适合边跑边看、探索性调试
```

**规则：**
- 用户回复“默认”或选定编号后，**先做轻量版逆向推演风险评估（见 `references/risk_premortem.md`，高风险 ≤5 条，与逻辑复述同轮输出）**。
- 快速脚本模式下，若轻量版推演中没有需要用户额外拍板的业务歧义，可在同一轮直接紧跟输出完整可运行代码；若发现新的口径歧义（如财务含税/不含税、右表关联键重复如何取舍），先给点选卡让用户拍板后再出代码。

## 何时输出 .ipynb 而非 .py

默认优先生成 `.py` 脚本（不依赖 Jupyter 环境），只有满足以下任一情况时切换成 `.ipynb`：
- 用户在点选卡中选了 `.ipynb`，或提到“notebook / ipynb / 想分步看结果 / 边跑边调 / 探索性分析”
- 任务本质是“先看看数据长什么样”、试探性清洗，需要反复交互式调整
- 生成 `.ipynb` 时用 `nbformat` 库构造合法的 notebook JSON 结构，不要手写拼接 JSON 字符串。

## 特殊模式自动触发（追加进开场点选卡）

### 财务严格口径模式
**触发词：** 金额 / 利润 / 成本 / 税 / 结算 / 应收 / 应付
触发后必须在开场点选卡中追加确认：
- **金额口径**：`● A. 含税金额` / `○ B. 不含税金额（需按税率折算）`
- **时间口径**：`● A. 记账日` / `○ B. 到账日` / `○ C. 开票日`
- **负数含义**：`● A. 退款/退货抵扣` / `○ B. 冲销单单独统计` / `○ C. 异常脏数据需标红拦截`

### 多表关联模式
**触发词：** 合并 / 关联 / join / 匹配 / vlookup / 链接表格 / 多表关联 / 跨表
触发后必须在开场点选卡中追加确认：
- **连接方式**：`● A. Left Join（保留左表全部，未匹配项单列提示）` / `○ B. Inner Join（仅保留两表共有）` / `○ C. Outer Join（全量并集）`
- **右表关联键重复保护**：`● A. 关联前对右表关联键做唯一性校验，若重复则报错阻断防行数翻倍（推荐默认）` / `○ B. 右表按关联键取第一条或先汇总再关联`

#### 架构设计：多表联动架构选择与分层原则

当面临多张 XLSX 表格联动时，**严禁两种极端走向**：
- ❌ **极端 1：纯 WPS/Excel 宏或自动化**（通过 COM 逐单元格遍历读写与公式计算，IPC 往返极其沉重，极易假死）；
- ❌ **极端 2：纯 Python 硬啃包含复杂原生公式和排版的 XLSX**（直接用第三方库重写含动态数组公式、外部链接的模板，易损坏公式）。

**最佳实践架构：Python 核心数据与业务逻辑层 + 可选 Office 表格引擎层**：
- **纯数据型表格（默认第一优先）**：`Polars (fastexcel) / Pandas (python-calamine) 读取 → 纯内存向量化计算 → xlsxwriter / openpyxl 输出`，零外部软件依赖。
- **复杂 Office 表格（含原生跨表公式重算、`ChangeLink` 外部链接刷新、打印排版保真）**：`Python 批量计算 → 一次性回填 → WPS 负责原生公式重算与格式保存`（详见 `references/patterns.md` 第 12、13 条）。

## 固定工具链（严格区分 Polars 与 Pandas 的 Calamine 依赖名）

| 环节 | 工具 | 关键说明（防踩坑必看） |
|------|------|------|
| Polars 读取 Excel | `fastexcel` | `pl.read_excel(file, engine="calamine")` 底层实际 import 的包是 **`fastexcel`**（绝不是 `calamine`） |
| Pandas 读取 Excel | `python-calamine` | `pd.read_excel(file, engine="calamine")` 底层实际 import 的模块名是 **`python_calamine`**（安装包名 `python-calamine`） |
| 数据计算 | `polars` / `pandas` | 大型表与常规批处理优先 `polars`；需复杂索引或老旧代码兼容用 `pandas` |
| 保存输出 | `xlsxwriter` / `openpyxl` | 新建输出优先 `xlsxwriter`（支持同文件多 Sheet 输出主结果+异常明细）；保留原模板样式/宏用 `openpyxl` |
| 超大文件（>2GB）| `polars` Lazy 模式 | 代码自动检测文件体积切换，无需用户确认 |
| 多文件（≥5个）| `concurrent.futures` | 代码自动判断并发读取，无需用户确认 |

## 代码生成规范

### 生成代码时：读取 `scripts/boilerplate.py` 作为起点

生成脚本前先读取 `scripts/boilerplate.py`，以它为骨架，只替换参数区和核心逻辑区，必须保留以下防翻车底座：
1. **准确的依赖自检**：Polars 路线检查 `"fastexcel": "fastexcel"`，Pandas 路线检查 `"python_calamine": "python-calamine"`，缺包时打印安装命令并以 **`sys.exit(1)`** 非零状态码退出。
2. **零静默丢弃空值**：存在空值行时，将空值行分离到 `null_rows_df` 并写入同一个输出 Excel 的 **`异常空值明细`** Sheet，严禁静默 `drop_nulls` 后直接丢弃。
3. **零值过滤安全**：过滤判断必须写 `if FILTER_COL is not None and FILTER_VAL is not None:`，防止过滤值为 `0`、`False` 或 `""` 时被跳过。

## 输出格式

每次代码生成必须包含四部分：

**① 依赖安装命令**（不得省略）
```bash
# Polars 极速路线（默认）
pip install polars fastexcel xlsxwriter numpy

# 若使用 Pandas 路线则为：
# pip install pandas python-calamine openpyxl xlsxwriter numpy
```

**② 需求确认与逆向推演防翻车落地总结**
- 最终确认的业务逻辑与工具组合
- 轻量版逆向推演风险表（R1~R5）及代码内对应的防护落点（如空值分流 Sheet、关联键去重校验、文件占用异常提示）

**③ Python 代码**（完整可直接运行，所有异常分支均带 `sys.exit(1)`）

**④ 结果与对账说明**
- 输出工作簿包含的 Sheet 清单（「结果」与按需生成的「异常空值明细」）、字段顺序与对账建议
