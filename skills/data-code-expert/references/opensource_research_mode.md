# 开源优先调研模式（Token 节省型规划，禁止跳过）

## 为什么要有这个模式

大型完整系统/平台如果一上来就“从 0 开始写代码”，单次 token 消耗大且极易因需求边界未收敛而返工。本模式通过**「开场点选澄清 → GitHub 开源方案五维调研 → 选型与 MVP 拍板点选卡 → 逆向推演与分阶段落地」**，花最小成本找到最优解。

## 强制流程（在用户拍板选型前，一行代码都不写）

### 第一步：输出「开场项目定位点选卡」
收到“我要做一个 XXX 系统/平台/网站/App”后，先对模糊边界输出结构化点选确认卡（带 `●` 推荐默认项，支持回复“默认”）：

```markdown
在为你检索 GitHub 现成开源方案并规划架构前，请确认以下关键边界（直接回复 **“默认”** 或 **“1A 2B”** 即可）：

**1. 系统核心定位与首期目标**
- `●` **A. 聚焦核心业务闭环的轻量生产系统（推荐默认）**
- `○` **B. 多租户 / 复杂权限的完整企业级平台**
- `○` **C. 内部团队工具 / 快速验证原型（MVP）**

**2. 开源选型偏好**
- `●` **A. 开源优先（推荐默认）**：优先找高 Star、近 1 年持续维护、支持 Docker/一键部署的 MIT/Apache-2.0 开源项目，不合适再基于五层架构自研
- `○` **B. 仅参考开源项目的交互与数据库设计，代码基于 Vue 3 + FastAPI 五层架构全新自研**

**3. 部署与终端形态**
- `●` **A. 响应式现代 Web 平台（支持局域网 Docker 或 Vercel + Turso 零成本云端上线，推荐默认）**
- `○` **B. 桌面客户端（Windows EXE）**
- `○` **C. 移动端 / 跨端应用**
```

### 第二步：去 GitHub 调研 3~5 个候选开源项目
逐个核查：① 最近 1 年是否仍在维护、② Star/社区活跃度、③ 部署复杂度（是否有 Docker）、④ 功能匹配度、⑤ 技术栈与开源协议（License 是否允许商用）。

### 第三步：输出调研对比表 + 「落地路径拍板点选卡」（禁止同轮直接写业务代码）
1. **候选开源项目对比表**（项目名、Star 数、最近更新、功能匹配度、License、优缺点）
2. **落地路径点选拍板卡**：
   - `●` **A. 基于五层架构 + 获奖级毛玻璃 UI 自主构建精简 MVP（推荐默认：当现成开源项目过于笨重或技术栈不符时）**
   - `○` **B. 直接部署候选项目 X 并做配置定制**
   - `○` **C. 基于候选项目 Y 进行二次开发**

### 第四步：逆向推演风险评估与分模块交付
用户拍板路径后，先按 `references/risk_premortem.md` 执行完整版逆向推演风险评估与 MVP 模块划分；若为 Web 端自研，严格遵循 `references/web_workbench_mode.md` 与 `references/web_ui_glassmorphism.md`（含 Awwwards 七维自检闭环）。
