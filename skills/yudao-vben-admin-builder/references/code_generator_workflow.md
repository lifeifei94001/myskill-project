# 芋道代码生成器与脚手架落盘流程 (Code Generator & Landing Workflow)

芋道的核心生产力来源于「代码生成器」：能自动生成 Entity、VO、Mapper、Service、Controller、API、前端列表/表单 Vue 页面以及菜单权限 SQL。

---

## 1. 代码生成器四步法

```
① 建表 (带标准字段) ➔ ② 导入代码生成器 ➔ ③ 配置元数据与模板 ➔ ④ 下载解压并落盘
```

### 第一步：在数据库执行建表 SQL
- 表名规范：`模块名_业务对象`，例如 `crm_customer`、`erp_purchase_order`。
- 必须带公共审计字段与租户字段（可运行 `python scripts/generate_yudao_ddl.py -t <表名> -c <注释>` 生成）。

### 第二步：导入表
1. 登录系统后台（管理员账号）。
2. 进入导航菜单：**「基础设施」 -> 「代码生成」**。
3. 点击 **「基于 DB 导入」**，搜索并选中刚才建立的业务表，点击确认导入。

### 第三步：配置生成规则
点击该表所在行右侧的 **「编辑」**：
1. **生成信息**：
   - **模块名**：如 `crm`、`erp`、`trade`。
   - **业务名**：如 `customer`、`order`。
   - **类名称**：系统会自动驼峰转换，如 `CrmCustomer`。
   - **前端模板**：根据所选前端，选择 `Vue3 (Element Plus)` 或 `Vben 5`。
   - **上级菜单**：选择要在哪个已有菜单节点下挂载（如挂在「客户管理」或某个一级分类下）。
2. **字段信息**：
   - 检查每个字段的页面展示类型（输入框、下拉框、单选、富文本、时间选择器）。
   - 绑定对应的字典类型（如状态绑定 `sys_common_status`）。
3. 保存配置，点击 **「生成代码」** 下载 `.zip` 压缩包。

## 4. 生成代码的安全落盘流程

根据当前 AI 运行环境的能力，执行不同的落盘方式：

### 模式 A：具备直接项目操作权限的环境 (如 Claude Code / 本地智能代理)
1. **解压放置**：
   - 将 `yudao-module-xxx` 目录合并覆盖至后端对应模块目录。
   - 将前端 Vue/TS 文件复制到前端项目的 `views/` 与 `api/` 目录。
2. **SQL 执行安全准则**：
   - **严禁直接在生产环境自动执行任何 SQL！**
   - 检查生成包内的 `sql/sql.sql`，确认菜单编号、上级菜单 ID 无冲突。
   - 在**本地开发数据库**执行前，先进行库备份。
3. **缓存刷新**：
   - 清除 Redis 中的菜单与权限缓存，或直接重启后端服务。
4. **角色授权**：
   - 告知用户登录后台，在 **「系统管理」 -> 「角色管理」** 找到对应角色，勾选新生成的菜单与按钮权限并保存。

### 模式 B：纯聊天交互模式 (无法直接操作文件系统)
1. 输出清晰的分步说明清单：
   - 哪些 Java 文件复制到后端的哪个绝对/相对路径。
   - 哪些 Vue/TS 文件复制到前端的哪个路径。
   - `sql.sql` 的具体内容，提醒用户在 Navicat / DataGrip 中手动执行。
2. 提醒用户重启服务并配置角色授权。

## 5. AI 增量开发流程 (禁止重写 CRUD)

代码生成器导入完成后，基础增量功能已经就绪。AI 的核心任务**仅限于增量业务逻辑**：
1. **业务校验**：在 `Service` 的 `create` / `update` 方法中补充防重、状态前置检查。
2. **状态流转**：订单流转、审核状态机。
3. **复杂联动**：主子表关联、级联计算。
4. **报表与导出**：自定义聚合查询或特殊格式导出。

> **增量开发第一动作：**
> 在动手写任何增量逻辑前，先在当前模块找同类业务已有的 `ServiceImpl` 方法，复用其现有模式与事务注解。
